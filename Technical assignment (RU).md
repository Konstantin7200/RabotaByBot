# Техническое задание — Бот уведомлений Rabota.by

> Сопроводительный документ: [`User stories (RU).md`](./User%20stories%20(RU).md)
> Определяет, **что** должно делать система, её рамки и ограничения. Технический дизайн
> (архитектура, модель данных, API) описывается отдельно в технической спецификации.

---

## 1 · Обзор

Мультипользовательский Telegram-бот, который отслеживает привязанные почтовые ящики Gmail
на предмет писем Rabota.by с ответами на отклики и отправляет уведомление в Telegram-чат
пользователя, привязавшего аккаунт.

**Цель продукта:** соискатели узнают об ответах (принят/отклонён) в течение минуты,
не проверяя почту.

---

## 2 · Область

### Входит в область

- Привязка / отвязка Gmail через OAuth для каждого пользователя Telegram
- Push-обнаружение писем (Gmail watch → Cloud Pub/Sub → вебхук)
- Фильтрация: только отклики Rabota.by
- Доставка уведомлений в правильный Telegram-чат
- Автоматическое продление watch; безопасное поведение при перезапуске

### Вне области

| Исключено | Причина |
|---|---|
| Фронтенд / веб-интерфейс | Telegram-бот — единственный интерфейс |
| Дополнительные агрегаторы | Отложено — см. US-9 |
| Глубокий разбор писем | Извлечение только вакансии / работодателя / исхода |
| Админ-панель, биллинг | Однопользовательский режим, личное распространение |
| Верификация Google | Первый релиз ≤ 100 пользователей (тестовый режим OAuth) |
| Хранение содержимого писем | Обрабатываются транзитно, не сохраняются |

## 3 · Функциональные требования

| ID | Требование | Источник |
|----|------------|----------|
| FR-1 | Бот поддерживает команды `/start`, `/status`, `/unlink` | US-1 – US-3 |
| FR-2 | `/start` инициирует OAuth Google (offline access, scope `gmail.modify`) со state, привязанным к chat ID | US-1 |
| FR-3 | Колбэк OAuth сохраняет email + refresh token и устанавливает Gmail watch | US-1 |
| FR-4 | Новые входящие письма обнаруживаются через push Gmail, а не поллинг | US-4 |
| FR-5 | Уведомление отправляется только для писем от Rabota.by, соответствующих шаблону отклика | US-5 |
| FR-6 | Уведомление содержит вакансию/работодателя и исход (best effort; запасной вариант — тема/сниппет) | US-4 |
| FR-7 | Каждое письмо порождает не более одного уведомления на пользователя | US-6 |
| FR-8 | Уведомления маршрутизируются только в привязанный чат | US-7 |
| FR-9 | `/unlink` останавливает watch, удаляет сохранённые учётные данные и прекращает уведомления | US-3 |
| FR-10 | Gmail watch продлевается автоматически до истечения его 7-дневного срока | US-8 |
| FR-11 | Перезапуск сервера не приводит к потере или дублированию уведомлений | US-8 |

## 4 · Нефункциональные требования

| Область | Требование |
|---------|------------|
| **Задержка** | Письмо получено → сообщение в Telegram доставлено ≤ 60 с (p95) |
| **Квоты** | Запас в рамках бесплатного лимита Gmail API (~10 000 операций/пользователь/сутки) — ожидаемый объём ничтожен |
| **Безопасность** | Refresh-токены шифруются при хранении; вебхуки аутентифицированы (secret token Telegram + аутентификация push Pub/Sub); OAuth state защищён от CSRF |
| **Доступность** | Одноинстансное размещение допустимо; корректное завершение по SIGTERM |
| **Ёмкость** | ≤ 100 пользователей (тестовый режим Google OAuth), распространение лично / в небольшой группе |
| **Наблюдаемость** | Структурированные логи для сценариев привязки, отправки уведомлений и продления; сбои видны через `/status` |

## 5 · Ограничения и выбор стека

| Вопрос | Решение |
|--------|---------|
| Среда выполнения | Node.js + TypeScript |
| HTTP-фреймворк | Express |
| Фреймворк бота | grammY — **режим вебхуков** |
| База данных | PostgreSQL |
| ORM | Drizzle (+ миграции drizzle-kit) |
| Gmail-клиент | `googleapis` |
| Транспорт push | Push-подписка GCP Pub/Sub → HTTPS-эндпоинт |
| Хостинг | Railway / Fly.io / Render (нужен публичный HTTPS) |

## 6 · Внешние интеграции

1. **Google Cloud** — проект с включённым Gmail API; топик и push-подписка Pub/Sub;
   право publish для сервис-аккаунта Pub/Sub; экран согласия OAuth в режиме *testing*
   (≤ 100 пользователей).
2. **Telegram** — бот создан через BotFather; вебхук зарегистрирован с secret token.
3. **Rabota.by** — адрес отправителя и шаблоны тем писем подтверждены по реальному
   образцу письма с ответом на отклик. *(Обязательный вход до реализации FR-5 / FR-6.)*

## 8 · Риски и их устранение

| Риск | Влияние | Устранение |
|------|---------|------------|
| Истечение 7-дневного watch молча останавливает push | Все пользователи теряют уведомления | Ежедневное cron-продление + предупреждение через `/status` |
| Крайний случай первого уведомления (нет предыдущего history ID) | Пропуск первого письма после привязки | Базовый снимок при установке watch; разница берётся только после него |
| Неизвестен точный формат писем Rabota.by | Фильтр/парсер не работает | Получить реальный образец письма до написания FR-5 / FR-6 |
| Повторная доставка Pub/Sub | Дублирование уведомлений | Дедупликация по ID сообщения / history |
| Требование верификации Google для публичных пользователей | Блокирует широкое распространение | Сначала тестовый режим; верификацию запланировать позже |
